Monte Carlo Simulation

Valuing an option by simulating the underlying — and checking the answer against a closed form.

Why this module exists. Week 11 was a full meeting on Monte Carlo simulation, but no reading was assigned and Professor Vo's exam note does not mention it. Treat this as lower priority than the derivatives modules: know how to describe and set up a simulation rather than expecting to run a large one under exam conditions.

Question 4

In Excel, which expression draws a standard normal random variable?



The problem

Value a European call by simulation: S0 = $50.00, K = $50.00, r = 5%, σ = 35%, T = 1 year, no dividends. Use 1,000 paths.

In Excel

A1: drift      = (r - 0.5*sigma^2)*T
A2: diffusion  = sigma*SQRT(T)

Column A (1,000 rows):  z   = NORM.S.INV(RAND())
Column B:  S_T = S0*EXP($A$1 + $A$2*A2)
Column C:  payoff = MAX(B2 - K, 0)

price = EXP(-r*T) * AVERAGE(C:C)
SE    = EXP(-r*T) * STDEV.S(C:C) / SQRT(1000)
RAND() is volatile. Every recalculation redraws every path, so your price changes each time you press F9. Paste-special the payoffs as values before reporting, or accept that the figure moves — that variability is the simulation error you are asked to quantify.

Enter your results

Drift = -0.01125, diffusion = 0.35. Black–Scholes gives $8.0642 exactly. A large reference simulation returns $8.1013, and the standard error at 1,000 paths is approximately $0.4252.

Your simulated value is graded against a tolerance of roughly three standard errors, because it should differ from the closed form — that is what a finite sample means. If your figure sits within about ±$1.28 of $8.0642, the simulation is working. Raising the path count to 10,000 would cut the standard error to about $0.1344 — the √n rule, and the reason Monte Carlo is expensive when high precision is needed.

Interpretation

1. When simulation earns its cost

Black–Scholes answered this question instantly and exactly. Why would anyone simulate?

Because the closed form exists only for a narrow class of problems. Monte Carlo is indifferent to the shape of the payoff, so it prices path-dependent instruments — Asian, barrier, lookback options — where no analytic solution exists. It handles multiple correlated underlyings, stochastic volatility, jump processes, and fat-tailed distributions without reformulation. It extends naturally to portfolio risk: simulate the joint distribution of returns and read VaR or expected shortfall off the simulated tail, which is precisely where a normal approximation fails for the non-normal series in this course. The cost is precision per unit of computation — the √n rule means halving the error takes four times the work — and the fact that results inherit every assumption in the data-generating process. Validating against a known closed form first, exactly as this module does, is how you establish the machinery is right before pointing it at a problem where you cannot check the answer.

2. The assumption that matters most

This simulation drew from a normal distribution. Given what the market-model module showed about return distributions, what follows?

That the simulation reproduces Black–Scholes because it assumes the same world, not because it independently confirms it. Drawing z from a standard normal makes terminal prices lognormal by construction, which is the Black–Scholes assumption. If the real return distribution is fat-tailed — and the market-model module found substantial excess kurtosis in a fairly ordinary equity, with cryptocurrency considerably worse — then both the simulation and the closed form understate the probability of extreme outcomes, and they do so in the same direction. Agreement between them is not evidence of correctness. The fix is to simulate from a distribution that matches the data: a Student-t, a jump-diffusion, a stochastic-volatility process, or a bootstrap from historical returns. That is Monte Carlo's actual advantage, and it is thrown away by defaulting to NORM.S.INV.
